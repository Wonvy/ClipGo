# ClipGo 视频号下载助手（Windows 实验版）

独立桌面工具，同时从微信主界面和独立视频窗口的工作进程中**只读提取已加载的视频地址**，再下载为 MP4。不注入代码、不修改微信、不接管网络，也无需证书或代理。

默认界面采用 **HTML / CSS / JavaScript + pywebview**，由 Windows WebView2 在独立窗口中显示本地网页。视频地址和解码参数保留在 Python 后端，网页只接收标题、作者、时长、图片和下载状态；界面无需联网加载字体、脚本或样式。

## 使用

1. 保持微信已登录，在主界面的「视频号」或独立视频窗口中播放目标视频几秒。
2. 打开 `ClipGoChannels.exe`，工具自动读取两处的视频并持续同步，无需切换来源。
3. 扫描结果分批显示，先出卡片与标题、再补封面。刷新只添加或更新记录，始终保留已有列表。点击对应卡片的 **下载**，默认保存到用户下载文件夹下的 `ClipGo视频号`。
4. 点击卡片或标题可在工具内播放。首次需要先准备完整视频，会显示进度；已准备或本次运行中已下载的视频直接复用本地文件。鼠标放在卡片上按 **空格** 也能打开播放器，播放时空格暂停或继续，Esc 关闭。
5. 自动同步在一次读取结束后约 4 秒再次检查，实际更新速度取决于微信加载和扫描耗时；可用右上方 **自动同步** 开关暂停，或点击 **刷新** 立即读取。新发现的视频靠前显示。
6. 顶部支持标题或作者搜索。保存位置、**打开文件夹** 和 **全部 / 已识别** 筛选收在右上角设置菜单中。封面用于辨认已加载的视频，不保证该卡片就是微信当前正在播放的内容。
7. 卡片右上角的删除按钮只移除该条列表记录；列表上方的 **清空** 可移除全部记录，包括被搜索或筛选隐藏的条目。已下载文件会保留，进行中的下载会继续。本次运行中，已移除的记录不会因刷新再次出现；新发现的视频仍会加入。
8. 卡片底部和播放详情按微信中的顺序显示四个图标及数字：喜欢、分享、点赞、评论。达到一万使用「万」显示，十万及以上显示「10万+」；悬停可查看完整数值。未读取到的数字显示「—」，不会当作零。

程序与 `_internal` 文件夹需要放在一起，不要只复制 EXE。下载过程中可以取消；网络等待中的取消需要等当前请求返回或超时。

窗口缩放时自动调整卡片列数，所有界面字号至少 12px。`Ctrl+F` 聚焦搜索，`Ctrl+R` 重新读取。需要 Windows 的 Microsoft Edge WebView2 运行时；本机已验证存在，无需额外安装。旧 Tk 界面仍可用 `ClipGoChannels.exe --legacy-ui` 启动。

## 已验证与限制

在本机 **Windows 微信 4.1.15.56** 上，已从独立播放窗口实际下载用户指定的《走进影视飓风和TIM聊聊人生与理想》：23 分 27.5 秒、576×1024、H.264 + AAC、70,665,556 字节。画面与用户截图相符，MP4 结构检查、FFprobe 信息检查及 FFmpeg 完整解码均通过。该条目在列表中显示时长 **23:27**。

微信主界面方式也曾成功下载一条 22.06 秒的篮球视频。上述结果只证明本机这些视频可用，不代表所有视频或微信版本都兼容。

- 微信可能预加载其他视频，列表不保证只包含正在看的那条。
- 主界面和独立窗口均从同一条视频数据的对象引用中取得标题、作者和封面；不按附近文本猜测。无法确认对应关系的条目显示“暂未读取到标题”，封面缺失或加载失败显示“暂无封面”。
- 四项互动数来自同一视频对象，随读取刷新；缺失字段保留之前已读到的值，不会清零。微信缓存中的数据可能落后于页面当前显示。
- 签名地址可能过期；失败时请重新播放并刷新列表。
- 只有完整 MP4 通过结构校验后才保存为最终文件；失败或取消会清理 `.part` 文件。
- 若视频本身加密，必须从同一播放信息对象中取得原始地址和匹配解码信息。不同签名地址不能共用一组解码信息，即使媒体标识相同。工具保留成对信息，最多尝试四组；缺少信息或解码不匹配时明确失败。
- 微信升级可能改变内存布局；无法核对结构时会跳过，不能保证仍能提取解码信息。
- 目前不支持直播录制或 DRM 内容。请只保存有权下载的内容。

## 读取范围

同时查找两类 `WeChatAppEx.exe --type=renderer` 工作进程：独立窗口使用 `--wmpf-render-type=7`，主界面使用 `--wmpf-render-type=6`。每种来源最多读取最新的两个进程，主界面优先、两类交替处理。打开句柄后再次核对路径和创建时间，防止进程编号复用。地址扫描每个进程最多读取 512 MiB 或 20 秒；只扫描可读私有内存，不申请写入权限。

只保留 `https://finder.video.qq.com/.../stodownload` 的完整视频签名地址，排除图片参数，并按媒体标识合并列表条目。支持 ASCII、UTF-16LE 和完整 JSON 字符串。两类窗口均做有界的 V8 媒体对象读取：核对描述符、对象类型和字段位置，通过 `objectDesc → media` 与同一视频的 `contact` 引用取得标题、作者和封面。主界面允许从同一媒体对象拼接原始地址和令牌，不要求拼接结果已经作为完整字符串存在；仍严格核对签名地址及配对解码信息。独立窗口额外限定为地址扫描中实际观察到的媒体。此阶段最多四轮、每轮 512 MiB，所有轮次合计限时 20 秒。不会扫描微信主进程、读取聊天数据库或保存内存转储。

重复读取复用经重新核验的结构地址，不缓存原始内存块；进程变化或结构失效时丢弃地址提示，至少每 30 秒重新发现结构，同时继续查找新媒体对象。初始地址和标题结果通过回调分批传给界面。网页轮询使用版本号，无变化时不重复传送整批封面。

封面只使用同一媒体对象提供的完整 `thumbUrl` / `coverUrl`，不借用视频地址的签名。后台只向已验证的 `finder.video.qq.com` 请求图片，拒绝跳转、不携带 Cookie 或使用系统代理；每张限制 8 MiB、8 秒和 1000 万像素，最多三路并发。缩略图仅保留在内存中，不保存到磁盘。

读取结果只在程序内存中保存，关闭窗口即释放。下载请求不附带微信 Cookie，不使用第三方解析服务。标题缺失时，文件使用通用名称及随机后缀，避免覆盖已有文件。

内置播放器通过仅监听本机的临时地址读取已校验 MP4，支持进度拖动；网页不接收微信签名地址或解码参数。首次播放会把视频准备到系统临时目录，关闭播放器撤销播放地址，正常退出工具时清理临时视频。缓存最多保留两个视频，超过 256 MiB 时淘汰旧视频（当前播放的单个视频可能超过此上限）。已下载到保存文件夹的视频不会随临时缓存删除。

读取失败会区分进程不可读、进程变化及未读取到数据。`%LOCALAPPDATA%\ClipGoChannels\last-web-state.json` 只记录最近一次读取与封面计数，不包含视频地址、标题、密钥或内存内容。旧 Tk 界面使用同目录的 `last-scan.json`。

## 实验网络监听（本机不推荐）

实验网络监听只保留在旧 Tk 界面的 **底部 ···** 中，新 HTML 界面不提供监听入口。**本机实测该模式会导致微信播放出错**，停止监听并移除临时证书后，用户确认恢复。原因尚未确定，不要用它替代已经可用的默认读取方式。

只有用户在确认框同意后，该模式才安装独立 HTTPS 根证书并启动按微信进程捕获。Windows 可能要求管理员授权。它限定 `Weixin.exe`、`WeChat.exe`、`WeChatAppEx.exe`，只解析 `channels.weixin.qq.com` 和 `finder.video.qq.com`，不修改系统代理、不保存完整抓包或 Cookie。Windows 对根证书的信任本身不受这些域名限制；域名限制由捕获配置实施。

停止监听会优雅关闭捕获服务并移除证书信任。服务会监测界面进程退出；异常关闭后仍可能留下证书记录，可点 **清理临时证书**。实际测试结束后，捕获已停止、临时证书信任已确认移除。

此模式的数据目录为 `%LOCALAPPDATA%\ClipGoChannels`：

- `session.json`：最多 200 条、最近 4 小时的媒体字段；正常停止时删除。
- `trusted-certificate.json`：本工具证书的精确指纹恢复记录；移除信任后删除。
- `certificate\`：独立 CA 和私钥；停止后仍保留，不要共享或上传。
- `instance.lock`：防止多个窗口同时管理同一证书。

## 开发与打包

需要 Windows、Python 3.12（兼容旧界面需含 Tkinter）、WebView2 运行时。在仓库根目录执行：

```powershell
py -3.12 -m venv build\wechat-venv
build\wechat-venv\Scripts\python.exe -m pip install -r tools\wechat_channels\requirements.txt
build\wechat-venv\Scripts\python.exe tools\wechat_channels\run.py
```

测试：

```powershell
build\wechat-venv\Scripts\python.exe -m unittest discover -s tests -p "test_wechat*.py"
```

浏览器界面测试 `tests/test_wechat_web_frontend.py` 使用可选的开发依赖 Playwright 和本机 Edge，未安装时跳过，不打入软件包。真实窗口诊断：

```powershell
build\wechat-venv\Scripts\python.exe tools\wechat_channels\run.py --diagnose-web build\wechat-html-check.json
```

此诊断会隐藏窗口，走完整网页与 Python 接口，检查真实条目、图片加载和横向溢出，只输出安全计数。

打包：

```powershell
powershell -ExecutionPolicy Bypass -File tools\wechat_channels\build.ps1
```

输出：`dist\ClipGoChannels\ClipGoChannels.exe`。构建脚本保留依赖许可证；本地开发包不包含微信数据、签名地址、密钥或下载视频。第三方说明见 `THIRD-PARTY-NOTICES.txt`。

## 分享安装包

朋友使用的发行版仅包含 HTML 界面及其运行依赖，不包含旧 Tk 界面和实验网络监听。与上面的本机开发包分开构建，版本独立于 ClipGo 浏览器扩展。

```powershell
powershell -ExecutionPolicy Bypass -File tools\wechat_channels\build-release.ps1 -Version 1.0.0
powershell -ExecutionPolicy Bypass -File packaging\wechat_channels\build-installer.ps1 -Version 1.0.0
```

输出为 `dist\ClipGoChannels-1.0.0-Windows-x64-Setup.exe`，分享这个完整安装程序即可。适用于 Windows 10 / 11 x64，安装到当前用户目录；已包含 Python。安装程序检查 .NET Framework 4.8 和 WebView2，缺少 WebView2 时通过微软原始安装程序联网安装。

发行构建、依赖校验和隔离安装测试详见 `packaging/wechat_channels/README.md`。随安装包保留原始第三方许可和简单使用说明；`release.json` 记录来源提交、版本和依赖，不包含个人数据。卸载按编译时的文件清单移除程序，保留已下载视频及额外用户文件。

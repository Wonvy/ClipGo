ClipGo 隐私政策

ClipGo 由浏览器扩展和安装在您电脑上的本地助手组成，用于将所选网站视频保存到您指定的文件夹。本政策说明当前版本实际访问、处理和保存的数据。不同发行版本支持的网站可能不同，以已安装版本和商店说明为准。

1. 访问和处理哪些数据

  • 视频页面信息：扩展会在支持的网站识别当前视频、卡片或播放器，读取相关链接、标题和视频标识，以显示下载按钮并确定下载对象。您粘贴或通过右键菜单选择的链接也会被处理。部分链接含有网站签名或访问参数，例如小红书的 xsec_token，会随任务链接保留。
  • 抖音网页视频信息：页面脚本会观察抖音网页正常发起的部分同源视频 JSON 响应，并读取页面初始数据。视频标识、标题、媒体地址及格式信息最多暂存 100 条于页面内存。选中视频的媒体地址可能包含临时签名；它会传给本地助手，但不会专门保存到扩展任务字段。找不到旧视频来源时，扩展可能暂时打开该视频的后台网页，获取匹配信息后关闭；您主动使用或导航的标签页会保留。
  • 登录状态和 Cookie：开始下载时，扩展按目标网站读取相关 Cookie（包括可能代表登录状态的值），经浏览器 Native Messaging 传给本地助手。Instagram、哔哩哔哩、X/Twitter、小红书、TikTok、抖音及腾讯视频使用相应网站范围的 Cookie；YouTube 仅在您开启“使用登录状态”选项时读取，默认关闭。已取得抖音网页直链时不另外导出 Cookie。
  • 任务、设置和本地路径：扩展在浏览器本地存储中保存任务链接、网站、标题、清晰度、状态、进度、时间、文件路径及错误信息，并保存清晰度、通知和按钮等偏好。本地助手的 config.json 保存您选择的下载目录。完成通知可能向操作系统显示视频标题。

2. 数据发送到哪里

当前代码没有将这些数据上传到 ClipGo 自建服务器的功能，也未加入分析统计、广告或自动崩溃报告服务。扩展与本地助手之间的通信在本机进行，但下载并不完全离线，Cookie 也并非永不离开本机：助手及下载引擎会向目标网站、其接口和媒体 CDN 发起请求，按网站认证需要发送相应 Cookie 或登录信息。腾讯视频还会将相关 Cookie 中的登录字段按其播放器机制传给腾讯的第一方视频 API。媒体请求会使用所选地址及其签名参数。

这些第三方会接收到请求所需的信息，例如 IP 地址、请求头、资源地址和适用的登录凭据，并按各自政策处理。后台打开的抖音网页也会像普通浏览网页一样与该网站通信。ClipGo 当前没有出售数据或向广告商共享数据的功能。

3. 本地保存时间与删除

  • 创建新任务时，扩展最多保留 30 条已结束任务，并另行保留进行中的任务；任务刚结束时，数量可能暂时超过 30 条。您可以移除单条记录或清空已结束任务。清空记录不会删除已下载文件或助手日志。
  • 下载文件保留在您选择的目录，默认是用户下载文件夹下的 ClipGo 文件夹，直到您自行删除。下载或合并中断可能留下部分文件。
  • 助手会将 Cookie 临时写入系统临时目录中的 clipgo_*.txt，将抖音媒体信息临时写入 clipgo_media_*.json。任务结束时会尝试删除这些文件；强制退出、系统崩溃或删除失败可能留下文件，需要您自行清理。
  • 助手目录中的 host.log 记录时间、版本、任务链接、清晰度、失败输出和异常。错误输出可能含文件路径、标题、媒体地址或签名参数。日志超过约 1 MB 时，会在下一次写入前删除重建；没有按天清理规则。请先检查并删去敏感内容再向他人分享日志。
  • 下载引擎可能使用自己的本地缓存保存客户端标识、签名等信息；当前助手未禁用其缓存。该缓存不属于扩展任务清单。页面内存中的抖音记录随页面关闭或重载释放。

您可以在浏览器设置中控制网站访问权限、停用或卸载扩展；也可以关闭完成通知、悬浮按钮或 YouTube 登录状态选项。Windows 助手卸载程序保留下载文件、config.json、host.log 和未知用户文件，不会替您清理浏览器扩展数据、系统临时目录或下载引擎缓存。若要清除这些本地数据，请分别在浏览器或相应文件位置处理。

4. 权限用途

nativeMessaging 用于与本地助手通信；storage 用于保存本地设置和任务；contextMenus 用于右键下载；cookies 用于上述网站登录状态；notifications 用于完成通知和部分操作错误提示；activeTab 用于您打开扩展时识别当前页。所列网站的主机权限用于在这些页面识别视频、读取相关 Cookie 和与页面脚本通信。扩展没有申请读取全部浏览历史的 history 权限。

5. 安装、更新与第三方组件

Windows 一键安装包包含 Python、yt-dlp、FFmpeg 和 Deno，安装这些已打包组件无需联网下载。手动安装脚本会从 Python 官方网站、GitHub 上相关项目的发布渠道获取组件；macOS 的 FFmpeg 来自 ffmpeg.martin-riedl.de。构建安装包时也会下载已锁定版本并核对 SHA-256。

您点击“更新下载引擎”时，Windows 助手调用 yt-dlp 自身更新功能，macOS 助手下载 GitHub 上 yt-dlp 的最新官方包并替换本地引擎。这些请求会向对应下载服务披露 IP 地址等连接信息，并可能跟随其下载 CDN 的重定向，不会附加扩展导出的目标网站 Cookie。

当前扩展脚本随扩展打包，不从远程加载执行代码。YouTube 支持版本中的原生下载引擎会使用本地 Deno 和官方可执行文件内置的 EJS 组件处理网站提供的播放器及验证脚本。yt-dlp 另有从 GitHub 或 npm 获取远程组件的能力，但当前助手不启用 --remote-components，下载命令也忽略用户的 yt-dlp 配置。引擎更新可能改变第三方行为，后续发布需要重新核对。参考：yt-dlp EJS 官方说明及当前锁定版本文档。

6. 联系与政策变更

开发者：Wonvy。隐私问题请通过 ClipGo GitHub Issues 联系。Issues 为公开页面，请勿提交 Cookie、登录凭据、私人文件或未脱敏日志。数据处理方式发生变化时，我们将更新本政策及日期。

ClipGo Privacy Policy

ClipGo consists of a browser extension and a helper installed on your computer. It saves selected website videos to a folder you choose. This policy describes data accessed, processed, and stored by the reviewed version. Supported sites can differ between distributions; consult your installed version and its store listing.

1. Data we access and process

  • Video page information: the extension identifies videos, cards, and players on supported sites and reads relevant links, titles, and video identifiers to display download controls and select the correct item. It also processes links you paste or select through the context menu. Site access parameters, such as Xiaohongshu's xsec_token, may remain in a stored task URL.
  • Douyin page media: a page script observes certain same-origin video JSON responses normally requested by the website and reads its initial page data. It keeps up to 100 video identifiers, titles, media URLs, and format records in page memory. A selected media URL may contain a temporary signature and is sent to the local helper; it is not intentionally stored as an extension task field. To retrieve a source for an older video, the extension may open its normal watch page in a background tab and close it afterward. A tab you take over or navigate is retained.
  • Cookies and login state: when starting a download, the extension reads target-site cookies, which may contain login credentials, and sends them to the local helper through browser Native Messaging. This applies to Instagram, Bilibili, X/Twitter, Xiaohongshu, TikTok, Douyin, and Tencent Video within their corresponding site scope. YouTube cookies are read only when its login-state option is enabled; it is off by default. An available Douyin page-media URL is used without additionally exporting cookies.
  • Tasks, preferences, and paths: browser local storage holds task URLs, sites, titles, quality, status, progress, timestamps, file paths, and errors, plus preferences such as quality, notifications, and quick buttons. The helper saves your download folder in config.json. Completion notifications may display video titles through the operating system.

2. Where data goes

The reviewed code has no feature that uploads this data to a ClipGo-operated server and includes no analytics, advertising, or automatic crash-reporting service. Communication between the extension and helper is local. However, downloads are not entirely offline, and cookies do not necessarily stay on your device: the helper and download engine request the target website, its APIs, and media CDNs, sending applicable cookies or login information as needed. For Tencent Video, relevant login fields are also extracted from cookies and sent to Tencent's first-party video API following its player mechanism. Media requests use the selected resource URL and its signature parameters.

These third parties receive information needed for the request, such as your IP address, request headers, resource URL, and applicable authentication details, under their own policies. A background Douyin page communicates with that site like an ordinary page visit. ClipGo currently has no functionality for selling data or sharing it with advertisers.

3. Local retention and deletion

  • When a new task is created, the extension retains up to 30 finished tasks plus active tasks. The finished count may temporarily exceed 30 as active tasks complete. You can remove individual records or clear finished tasks. This does not delete downloaded files or helper logs.
  • Downloaded files remain in your chosen folder, by default ClipGo inside your user's Downloads folder, until you delete them. Interrupted downloads or merges may leave partial files.
  • Cookies are written to temporary clipgo_*.txt files, and Douyin media information to temporary clipgo_media_*.json files, in the system temporary directory. The helper attempts deletion after the task; a forced exit, crash, or deletion failure may leave files for you to remove.
  • host.log in the helper folder records timestamps, versions, task URLs, quality, failure output, and exceptions. Error output may include paths, titles, media URLs, or signature parameters. A log larger than approximately 1 MB is deleted before the next write; there is no time-based expiry. Review and redact sensitive information before sharing a log.
  • The download engine may maintain its own local cache of information such as client identifiers and signatures. The helper does not disable that cache, which is separate from the extension task list. In-memory Douyin records are released when the page closes or reloads.

You can manage website access in browser settings, disable or uninstall the extension, and turn off notifications, quick buttons, or YouTube login-state use. The Windows helper uninstaller preserves downloads, config.json, host.log, and unknown user files. It does not clear browser extension data, system temporary files, or the engine's cache. Remove those separately through your browser or the relevant file locations.

4. Why permissions are requested

nativeMessaging communicates with the local helper; storage saves local tasks and preferences; contextMenus provides right-click downloading; cookies provides the login-state handling described above; notifications reports completion and some operation errors; and activeTab identifies the current page when you open the extension. Listed website host permissions enable video identification, relevant cookie access, and page-script communication on those sites. The extension does not request the history permission to read your entire browsing history.

5. Installation, updates, and third-party components

The Windows installer bundles Python, yt-dlp, FFmpeg, and Deno, so installation of those bundled components does not download them again. Manual installation scripts retrieve components from Python's official website and the relevant GitHub project releases; macOS FFmpeg comes from ffmpeg.martin-riedl.de. Building the installer also retrieves pinned components and verifies their SHA-256 hashes.

When you select “Update download engine,” the Windows helper runs yt-dlp's updater; the macOS helper retrieves the latest official yt-dlp package from GitHub and replaces its local engine. Download services receive connection information such as your IP address, and requests may follow their CDN redirects. These update requests do not receive the target-site cookies exported by the extension.

Extension scripts are packaged with the extension and do not load executable code remotely. In editions supporting YouTube, the native engine uses local Deno and EJS components bundled in official executables to process site-provided player and challenge scripts. yt-dlp can optionally fetch components from GitHub or npm, but the current helper does not enable --remote-components and its download command ignores user yt-dlp configuration. Future engine updates can change third-party behavior and require review. See the official EJS documentation and the pinned version's documentation.
